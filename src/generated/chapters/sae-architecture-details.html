C SAE Architecture Details and Hyperparameters#

This appendix provides practical guidance for training and evaluating Sparse Autoencoders.

C.1 Standard SAE Architecture#

A Sparse Autoencoder reconstructs activations h \in \mathbb{R}^{d} via:

Encoding: z = \text{ReLU}(W_{\text{in}} h + b_{\text{in}})

where z \in \mathbb{R}^{d_{\text{sparse}}} (sparse features), d_{\text{sparse}} \gg d, W_{\text{in}} \in \mathbb{R}^{d_{\text{sparse}} \times d}

Decoding: h' = W_{\text{out}} z + b_{\text{out}}

where W_{\text{out}} \in \mathbb{R}^{d \times d_{\text{sparse}}}

Loss: \begin{equation*} \mathcal{L} = \|h - h'\|^2 + \lambda \|z\|_1 \tag{6} \end{equation*}

where \lambda is the sparsity coefficient (typically 0.001–0.01).

C.2 Standard Hyperparameters#

For a baseline SAE on a 4096-dimensional residual stream:

  • SAE expansion factor: d_{\text{sparse}} = 4 \times 4096 = 16384 (4x expansion is standard)

  • Learning rate: 10^{-3} to 10^{-4} (Adam optimizer, warmup of 500–1000 steps)

  • Sparsity coefficient \lambda: 0.001 to 0.01 (higher \lambda = sparser features, lower reconstruction)

  • Batch size: 16–64 (memory-limited; smaller batches for multi-GPU training)

  • Training duration: 50K–500K training steps (depends on dataset size and desired convergence)

  • Initialization: random normal for W_{\text{in}}, orthogonal for W_{\text{out}} (improves stability)

C.3 Gated SAE Variant#

Gated SAEs solve the shrinkage problem by learning a separate “gate” for each feature:

Encoding: z = \sigma(W_{\text{gate}} h + b_{\text{gate}}) \odot \text{ReLU}(W_{\text{in}} h + b_{\text{in}})

where \odot is element-wise multiplication and \sigma is sigmoid.

This allows features to be individually gated on/off, improving feature quality.

Sparsity penalty: applied to \sigma(W_{\text{gate}} h + b_{\text{gate}}) (the gate activations, not the ReLU outputs).

Gated SAE hyperparameters:

  • Same expansion factor and learning rate as standard SAE

  • Sparsity coefficient often slightly higher (0.01–0.05) to encourage gate closure

  • Additional weight decay on gate parameters (0.01) to prevent gate collapse

C.4 Top-K SAE Variant#

Top-K SAEs replace soft sparsity (\ell_1 penalty) with hard sparsity (exactly k features active):

Encoding: z = \text{top-}k(\text{ReLU}(W_{\text{in}} h + b_{\text{in}}), k)

where \text{top-}k returns a vector with only the k largest values, rest zero.

No sparsity penalty needed; sparsity is enforced structurally.

Top-K hyperparameters:

  • k: typically 50–200 (aim for 5–10% of d_{\text{sparse}} active)

  • Learning rate: slightly higher (10^{-3}) since there’s no sparsity penalty

  • Auxiliary loss: use auxiliary learning rate to balance training across different k values

C.5 Evaluation Metrics#

Standard metrics for SAE quality:

  • Reconstruction loss: \mathbb{E}[\|h - h'\|^2] (how well does the SAE reconstruct the original?)

  • Loss recovery: \frac{\mathcal{L}_{\text{model}} - \mathcal{L}_{\text{model w/ SAE}}}{\mathcal{L}_{\text{model}}}  (what fraction of model loss is recovered by SAE reconstruction?)

  • Sparsity: mean number of features active per example (target: 10–100 depending on layer)

  • Feature quality: how interpretable are the extracted features? (subjective, can be evaluated via automated explanations)

  • Absorption ratio: how much downstream computation depends on SAE features vs. residuals?

C.6 Training Stability Tips#

  • Orthogonal initialization of W_{\text{out}}: improves convergence and feature quality

  • Warmup: start with \lambda = 0 for 500–1000 steps, then ramp to full sparsity coefficient

  • Learning rate schedules: cosine annealing or exponential decay in later training helps convergence

  • Batch normalization: can help but not always necessary; test both

  • Gradient clipping: if loss spikes, clip gradients to norm 1.0

  • Monitor dead features: track percentage of features never activated; if > 20%, increase learning rate or decrease \lambda

C.7 Multi-Layer SAEs#

For analyzing multiple layers, train separate SAEs per layer. Key considerations:

  • Scaling expansion factor: early layers need fewer features (simpler patterns), later layers need more (complex abstractions). Use 2x expansion early, 8x expansion late.

  • Coordinated training: train all SAEs simultaneously vs. sequentially. Simultaneous training enables cross-layer analysis.

  • Feature alignment: after training, align features across layers to track evolution (using orthogonal Procrustes)
